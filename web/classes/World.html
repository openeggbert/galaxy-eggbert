World

The voxel world: a cubic grid of palette-compressed chunks, sparse per-block metadata, a block change journal, and the .vwr file reader and writer.

Location

Headerinclude/GalaxyEggbert/Worlds/World.hpp
Sourcesrc/GalaxyEggbert/Worlds/World.cpp
NamespaceGalaxyEggbert::Worlds
Depends onChunk, Block, VoxelConfig, BinaryIO.hpp (little-endian helpers)

Purpose

World is the single data model of a Galaxy Eggbert level. It has no CNA or cna-engine dependency: the game, the in-game editor, the renderers, the command-line verifiers and the unit tests all use the same class. Every campaign world in worlds3d/, every player's custom world and every galaxy world is one World saved as a .vwr file.

  • Grid. chunksPerAxis³ chunks of 10 × 10 × 10 blocks. The default (and the only size the game uses) is 10 chunks per axis: 100 × 100 × 100 blocks, 1000 chunks. Y is up.
  • Blocks. Each cell holds a 16-bit Block (12-bit type = the object-m.png icon number, 4-bit metadata). Air is 0.
  • Sparse metadata. Any cell can carry extra typed byte payloads (objects, BigDecor, tile turns, hint zones, player starts). They are stored per chunk and survive save/load; see The .vwr Format for the type list.
  • World-level header fields. Sky region (background picture), music track, mission number, an optional Blupi start cell, and the "legacy saw floors" flag.
  • Change tracking. A revision counter and a bounded journal of the last 256 block changes, so the terrain renderer can patch a few cells instead of rebuilding the whole mesh.

Coordinates are always raw grid cells, 0 to blocksPerAxis() - 1. The game's render space is shifted by 50 on X and Z (WorldRuntime::kWorldCenterX/Z); World never applies that shift.

How it is used

Loading and saving

The minimal round trip (from World Format.md):

#include "GalaxyEggbert/Worlds/World.hpp"
using namespace GalaxyEggbert::Worlds;

World world;
const Block grass = Block::make(1, 0);
world.setBlock(10, 5, 10, grass);
world.saveToFile("level.vwr");

World loaded = World::loadFromFile("level.vwr");
return loaded.getBlock(10, 5, 10) == grass ? 0 : 1;

In the game, WorldRuntime::LoadFromVwrStream() (src/GalaxyEggbert/Game/WorldRuntime.cpp) wraps the loaded world in a std::unique_ptr, runs the legacy saw-floor upgrade and then derives objects, BigDecor and hint zones from the sparse metadata. See WorldRuntime.

Patching the terrain from the change journal

When a door opens, a bridge crumbles or a switch flips the saws, the game changes blocks through setBlock(). Each frame GalaxyEggbertGame::RefreshTerrainMeshIfChanged() (src/GalaxyEggbertCNA/GalaxyEggbertGameLoad.cpp) compares revisions and asks for the changes since its last build: 

if (terrainRenderer_ && (worldRuntime_.GetWorld().blockRevision() != terrainRevision_ || ...))
{
    const auto& world = worldRuntime_.GetWorld();
    const auto changes = world.blockChangesSince(terrainRevision_);
    if (... && terrainRenderer_->PatchModelCells(world, changes, StillModelIcons(), ...))
    {
        terrainRevision_ = world.blockRevision();
        return;            // only the changed model cells were redrawn
    }
    ...                    // otherwise: full TerrainRenderer rebuild
}

Who uses it

  • WorldRuntime owns the live world during play and in the editor.
  • BlupiController reads blocks for collision (see Collision).
  • TerrainRenderer builds the meshes from it; InteractionSystem opens doors and changes tiles through it.
  • WorldEditor edits it in place; CustomWorldStorage saves it.
  • The record codecs (MoveObjectRecord, BigDecor, hint zones, player starts) and HubDoors are free functions over a World.
  • tools/vwr_inspect.py and tools/worldkit.py re-implement the reader and writer in Python; keep them in step with World.cpp.

Behaviour worth knowing

  • The header version byte must be exactly 2 (VoxelConfig::FormatVersion). Version 1 files are rejected, not upgraded.
  • Unknown header flag bits, a wrong chunk size, a chunk count that is not chunksPerAxis³, or a half-set spawn (one or two of the three spawn fields zero) are all load errors.
  • Loading never rewrites a file. A legacy file (flag bit 0 clear) round-trips byte-identically until something saves the upgraded world.
  • Changing the world-level fields (mission, sky, music, spawn) does not bump blockRevision(); metadata edits do, and they clear the journal.

Tests

  • tests/GalaxyEggbert/Worlds/WorldTests.cpp (GoogleTest, target GalaxyEggbertWorldsTests): dimensions, get/set across chunk boundaries, bounds checks, sparse metadata across chunks, save/load of blocks, metadata, sky region, music track, mission number and spawn point, legacy all-zero spawn slots, rejection of v1 files, bad magic, unknown flags and a wrong chunk count, BlockRevisionCountsBlockChanges, and IndependentSawFlagIsPreservedWithoutRewritingLegacyData.
  • tools/VerifyShippedWorlds.cpp (ctest VerifyShippedWorlds): every world in worlds3d/ loads, has the mission number its file name says, gives WorldRuntime its objects and survives load → save → load with identical metadata.
  • tools/VerifyTileFaces.cpp: drives blockChangesSince() through the terrain patch path and checks incremental and full rebuilds agree.
  • The editor verifiers (VerifyGEWorldEditor, VerifyGEEditorStorage, VerifyGEEditorObjects) save and reload worlds through it.
