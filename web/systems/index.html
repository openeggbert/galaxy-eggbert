Systems

Each game system, the code that implements it, and the page that explains it.

A "system" here is a behaviour the player sees, such as swimming or hub doors. Most of them are spread over a few files rather than owned by a single class. The tables name the main code; paths are relative to src/. In the play phase the systems run in a fixed order once per 1/60 s tick (Game Loop).

One boundary to keep InteractionSystem knows nothing of BlupiController, the camera or the graphics. It reports events (Blupi died, a pickup was taken, a voyage to another world is requested), and the host applies whatever needs the controller, camera, HUD or sound. Most systems below are wired through that boundary (Architecture).
