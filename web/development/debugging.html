Debugging

In-game diagnostics, the flags and environment variables the code reads, and how to reproduce a problem headless (checked against the source on 2026-11-10).

In-game diagnostics

Typed cheat words work in Play when the build has cheats enabled (the CMake option GALAXY_EGGBERT_ENABLE_CHEATS, ON by default; OFF compiles out typed words, F12 and the hidden cheat menu). The full list is on Cheats & Diagnostics; these are the ones that help when debugging:

Word or keyEffect
debugToggles the diagnostics panel (only in Play): simulation time and ticks, mission and sky region, lives, Blupi's raw position and cell, velocity in blocks/s, yaw, movement mode (ground or air, vehicle), animation state and icon, game speed, keys and touches held, gamepad and accelerometer state. Upper right on desktop, upper centre on touch layouts. Lines built by src/GalaxyEggbert/Game/DebugOverlay.hpp
positionShows Blupi's place (x, y, z) in the active cheats' list, with the world's X, Y and Z axes drawn as arrows that turn with the camera
fpsShows the frames drawn per second in the cheats' list
ghost, megablupi, zoomWalk through walls; invincibility; step the chase camera out
help / cheats, F1A paused overlay listing every cheat word; F1 shows the controls help
F5, F6, TabNormal and fast game speed; Tab steps slow motion 0.5, 0.25, 0.125 and back. F7/F8 (faster still) only after the quick cheat
F12The cheat menu

fairplay turns the toggles off and locks cheat entry (typing it again unlocks); honest locks every cheat until the game quits. If a debugging word does nothing, check for those.

Command-line flags

Parsed in src/GalaxyEggbertCNA/main.cpp. Run the game from its build directory, where a post-build step stages its assets.

FlagEffect
--mission NSkip the menus and start mission N
--spawn x,y,z[,yaw]With --mission: place Blupi at that raw grid position (yaw 0 faces -Z, 90 faces +X)
--autoplay <script>Play the mission by a QA script, write autoplay_trace.txt, exit 0 when it passed (Testing & QA)
--galaxyWith --mission: start from the selected player's own galaxy
--golden-capture, --golden-capture-traceThe deterministic captures behind tests/golden/
--record-demo <file>, --demo-ticks N, --demo-title <text>, --verify-demo <file>Record a main-menu demo; replay one and compare its end state (tools/record_demo.sh, tools/verify_demos.sh)
--user DIRKeep the player's files (savedata.txt, resume.txt, demos/, customworlds/) in DIR instead of the system's per-user folder; GALAXY_USER_DIR does the same
Use a scratch user folder Since 2026-11-10 a desktop build keeps the player's files in the per-user data folder ($XDG_DATA_HOME/Galaxy Eggbert on Linux). When you experiment with saves, resume or the editor, pass --user with a throwaway directory so your own progress is not touched. The QA scripts already set GALAXY_USER_DIR to their run directory.

Headless runs

The game needs a GL context. Under Xvfb, keep it silent with the dummy audio driver, as the QA scripts do:

cd build-cna-opengl3
SDL_AUDIODRIVER=dummy SDL_VIDEODRIVER=x11 xvfb-run -a -s "-screen 0 1280x720x24" \
    ./GalaxyEggbert --user qa-user --mission 12 --spawn 48,1,68,0

For anything you want to repeat, prefer the scripts: tools/autoplay.sh for gameplay and tools/qa_live.sh for screenshots (Testing & QA). Intermittent loss of window focus or input has been seen under Xvfb; it has not been traced to a defect in this code.

Reproducing a gameplay bug

  1. Start at the place: --mission N --spawn x,y,z,yaw (the debug panel's cell line gives raw coordinates).
  2. Write a short probe script (tools/autoplay/probes/ holds examples) with trace N to log every tick, shots N to save frames, and mortal to keep going past a death; run it with tools/autoplay.sh. The run is deterministic, so it reproduces the same way every time.
  3. Compare with the original's code (Decor.cpp and friends in mobile-eggbert) and search the ledgers before changing anything.
  4. Turn the reproduction into a test that fails without the fix (usually in VerifyBlupiMovement or VerifyInteractionSystem).

Context loss (F9)

On native desktop builds, CNA's runtime maps F9 to a simulated GL context loss and recreation. Use it to check that textures and meshes come back. The black distant floor seen after F9 was a CNA defect (upstream_bugs.md UB-009: only the base mip level was restored), fixed in CNA; the game has no workaround of its own.

Logs

  • The game writes its messages to standard output, prefixed GalaxyEggbertCNA: (for example the relief count and 3D effects: lines when a shader or render target cannot be made).
  • The QA scripts keep the game's output as game.log in their run directory, next to autoplay_trace.txt.
  • Android: adb logcat -s SDL SDL/APP GalaxyEggbert shows the game's and CNA's output (ANDROID.md).

API documentation (Doxygen)

When CMake finds Doxygen, it adds the target GalaxyEggbertDocs (cmake --build build-cna-opengl3 --target GalaxyEggbertDocs), which runs Doxygen in the build directory with a configured copy of the repository's Doxyfile. That file leaves INPUT empty and RECURSIVE = NO, so as committed it does not point Doxygen at the sources; the output has not been checked for this page. The headers' own comments (and the Classes pages) are the better reference.
