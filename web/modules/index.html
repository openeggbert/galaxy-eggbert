Modules

The source tree grouped by what each part is responsible for (as of 2026-11-10).

The code has about 66 000 lines: 178 source files under src/ and 31 headers under include/. It is layered: an engine-independent world model at the bottom, the game and the editor above it, and a thin CNA application host on top (Architecture). The groups below are a reading aid, not separate libraries. Most of them live in the same directory, src/GalaxyEggbert/Game/ (namespace GalaxyEggbert::Game).

ModuleWhereDepends on CNA?
World data modelinclude/GalaxyEggbert/, src/GalaxyEggbert/Worlds/, src/GalaxyEggbert/*.cppNo (enforced)
Game simulationsrc/GalaxyEggbert/Game/Mostly no

World data model

The voxel world and the original's data, with no CNA or cna-engine include, so it can be unit-tested without a window. Namespaces GalaxyEggbert::Worlds and GalaxyEggbert.

PartFilesWhat it holds
Voxel containerWorlds/World, Chunk, Block, BlockMetadata, VoxelConfig, BitPacking, BinaryIO, GridRaycast.hpp A 100×100×100 grid in 10×10×10 chunks with palettes, bit packing, sparse metadata and a change journal; .vwr load and save. See World.
The original's enumsDef/*.hpp (ObjectType, BlupiAction, SoundChannel, SpriteChannel, GamePhase, GameSpeed, …) Numbers that are stored in world files and must never change.
Block factsBlockTypes.hpp, BlockDefinitionRegistry, UnverifiedRenderMapping.hpp One definition per block icon 0-440: render mode, collision, animation, role flags. See BlockDefinitionRegistry.
RecordsMoveObjectRecord, BigDecorRecord, HintZoneRecord, PlayerStart.hpp Codecs for the sparse metadata stored in a world. See MoveObjectRecord.
HubsHubDoorsMission doors, gold doors, world signs and arrivals. See HubDoors.
ConstantsGameConstants.hppGrid size, the original's 640×480 logical screen, sprite cell size.

Game simulation

The rules of play. These parts run on the fixed 1/60 s tick, are deterministic, and mostly see only the World and plain numbers, which is what lets the Verify* tools drive them headless.

Application host

src/GalaxyEggbertCNA/ holds the XNA Game subclass GalaxyEggbertGame and everything platform-specific. It is split by concern:

FileConcern
main.cppCommand-line flags, the user folder, Run()
GalaxyEggbertGame.cppConstruction, input capture, music and vehicle sounds, voyages, cheats, full screen, focus loss and exit
GalaxyEggbertGameLoad.cppLoadContent() and building a world's presentation (terrain, models, reliefs)
GalaxyEggbertGameUpdate.cppUpdate() and the simulation tick UpdateTick()
GalaxyEggbertGameMissions.cppAutoplay steps, loading worlds (campaign, editor, galaxy, title scene), hub doors and phases
GalaxyEggbertGameScene.cppReading the simulation into the SceneFrame
GalaxyEggbertGameDraw.cppThe frame: world, HUD, menus, editor, captures
GalaxyEggbertGameDemo.cppThe resume log, the main-menu demos and the player's recordings
GameHelpers.hpp, GameInternal.hppHelpers shared by the files above
AndroidAssets.cppCopying the assets to internal storage on Android

Tools and tests

  • tests/GalaxyEggbert/: GoogleTest unit tests of the world model and records.
  • tools/Verify*.cpp: headless verification executables run by ctest.
  • tools/worlds/: one Python generator per campaign world plus shared kits.
  • tools/autoplay/: scripted playthroughs; tools/*.sh: QA scripts.
  • tools/rd4_to_gltf/, tools/terrain_relief/, tools/music/ and others: asset converters.

See Testing & QA and Assets & Tools.
