Assets & Tools

What the game loads, where each asset comes from, and the scripts that produce the generated ones (as of 2026-11-10).

Never edit a generated file by hand. Each runtime asset is either a copy of the original's media or the output of a script in this repository. Change the script or its input table and regenerate: avatars3d/**, tools/data/blocks.csv, BoltPaths.hpp, GlueStrands.hpp, LavaSurfaceData.hpp, textures3d/grass_top.png, worlds3d/*.vwr and plans/inventory/*.md are all generated.

The game opens every asset relative to its working directory. A desktop build copies Content/, worlds3d/, textures3d/ and avatars3d/ next to the executable after each link (changed files only). The web build packs Content/icons, backgrounds, sounds, demos, worlds3d, textures3d and avatars3d into its .data file and serves Content/music/ beside the page. Android packs the same directories into the APK (without the 2x sheets) and, before the game starts, copies them to internal storage when they are missing or come from an older build (AndroidAssets.cpp).

The tile sheet object-m.png

Every terrain block's texture is an icon of this sheet, and a block's type number is its icon number. The sheet is 1301 × 1431 pixels: 64-pixel tiles with a 1-pixel gap before each (a pitch of 65), 20 columns by 22 rows, so 440 slots, icons 0-439. Icon n starts at pixel (1 + 65 × (n mod 20), 1 + 65 × ⌊n / 20⌋). BlockTypes::tileUV() (include/GalaxyEggbert/BlockTypes.hpp) adds a half-texel inset so filtering never samples the neighbouring tile. The block registry has 441 entries (0-440); icon 440 lies outside the sheet, a known gap that VerifyTileUvBounds tracks.

For the terrain the game builds a padded copy in memory (1920 × 2112: each tile with a 16-pixel border of its own edge texels, a pitch of 96) and mipmaps it, so distant floors do not shimmer (TileAtlas). It also classifies every tile by its alpha channel as opaque, cut-out or translucent (TileCoverage.hpp), which picks the pass the tile is drawn in (Rendering).

Models from the original scenes: tools/rd4_to_gltf/

The original's sprites were rendered from Ray Dream Designer / Studio scenes. This toolchain reads those scenes, rebuilds their geometry, and checks each result against the sprites. Its README.md records every verified convention of the format.

  1. rd4.py, primitives.py, freeform_mesh.py, geometry.py and scene.py parse the ASCII scenes and build cones, spheres, cylinders, free-form surfaces and deformers.
  2. rd4_to_gltf.py converts one animated scene into a skinned glTF (gltf.py writes it), one joint per scene object.
  3. scene_render.py, render_cna.py and verify_sprites.py render with the original game camera and compare with the sprite icons by silhouette IoU (intersection over union).
  4. export_cna_avatar.py runs CNA's own converter (tools/avatar_asset_pipeline/convert_avatar.py in the CNA repository) to write CNA's SkinnedModelEXT directory, then fixes winding and per-part colours and textures.
  • Blupi: match_icons.py finds the scene frame each icon of blupi.png came from; build_clip_library.py makes one clip per BlupiController::AnimState, playing its icon table at 20 frames a second. Command lines are in avatars3d/blupi/README.md. Compare a rebuild clip by clip before replacing anything.
  • Objects: tools/rd4_to_gltf/objects.txt has one line per object (sheet, icon range, scenes, options such as yaw=, tone=, min_iou=). build_object_library.py and export_objects.py write avatars3d/objects/<name>/ with its icons.txt and rewrite index.txt; calibrate_tone.py suggests colour tones; procedural_materials.py writes materials.txt. Commands are in avatars3d/objects/README.md.
  • Special cases: sign_decals.py, dynamite_sparks.py, electro_sparks.py, top_texture.py, saw_upper_half.py, lower_spheres.py.

These tools need sibling checkouts: the original scenes (speedyblupi-data), Mobile Eggbert's sheets and CNA. Without them you can still build, play and test the game, but not regenerate models.

Terrain reliefs: tools/terrain_relief/

tiles.txt says which scene belongs to which tile icon (reviewed by eye); match_tiles.py ranks candidate scenes; build_relief.py keeps each scene's front half, decimates it to about 700 triangles with headless Blender (blender_decimate.py), cuts it along the cell's edges, textures it with the tile's sprite and writes avatars3d/terrain/*.gtr and index.txt. reliefs.txt holds per-model options. Tiles without a scene stay textured cubes.

Provenance and licences

docs/provenance/ is an inventory with evidence, taken on 2026-11-07; it is not legal advice and decides nothing. In short:

  • The repository is GPLv3 (LICENSE); this website (web/) carries its own MIT licence.
  • Sprites, backgrounds, sounds and the five level files are copies of Mobile Eggbert's (MIT); the original game is by Daniel Roux and EPSITEC SA. The repository records no grant from the original's authors for the media as such.
  • The models are generated from the original Ray Dream scenes, which the repository labels "GPLv3, © Daniel Roux & EPSITEC SA".
  • The music's MIDI source and the soundfont used for rendering are not recorded.
  • The fox placeholder's rig and animation are CC BY 4.0 and need attribution (recorded in its README).
  • Engine dependencies are sibling checkouts, not vendored: CNA (Ms-PL), cna-engine, easy-gl, sharp-runtime (MIT), SDL3 and SDL3_mixer (zlib).

The open questions are listed in docs/provenance/README.md and licences.md; per-asset detail is in original-game-material.md, generated-assets.md and third-party.md.
