# 6. Assets and the tools that make them

Principle: **do not hand-edit a generated asset.** Each runtime asset below either was copied from
the reference under the owner's approval, or is produced by a script in this repository from an
original source. Change the script or its input table and regenerate. Converter outputs and probes
go to `build-probe/`, never `/tmp`.

This chapter describes the tools from this repository's own files. The original source data
(Ray Dream scenes, Amapi shapes, MIDI music) lives in sibling repositories and is not described
here beyond what the tools say about it.

## Models: `tools/rd4_to_gltf/`

The original sprites were rendered from 3D scenes made in Ray Dream Designer 3 / Studio 4. The
toolchain turns those scenes into the models the game draws and checks them against the sprites.
Its own `tools/rd4_to_gltf/README.md` records every verified convention of the scene format.

Pipeline:

1. `rd4.py`, `primitives.py`, `freeform_mesh.py`, `geometry.py`, `scene.py` read the ASCII scene
   format and build geometry (cones, spheres, cylinders, free-form surfaces, deformers).
2. `rd4_to_gltf.py` converts one animated scene into a skinned glTF (`.glb`), one joint per scene
   object. `gltf.py` writes it.
3. `scene_render.py`, `shading.py`, `render_cna.py` render scenes or exported models with the
   original game camera; `verify_sprites.py` compares a render with the sprite icons by silhouette
   IoU (intersection over union) and writes comparison sheets.
4. `export_cna_avatar.py` runs CNA's own converter (`tools/avatar_asset_pipeline/convert_avatar.py`
   in the CNA repository) to produce CNA's `SkinnedModelEXT` directory, then fixes what that
   converter leaves (triangle winding for XNA's culling, per-part colours and textures; see
   `upstream_bugs.md` UB-001..UB-003).

**Blupi.** `match_icons.py` finds which scene frame each sprite icon of `blupi.png` was rendered
from; `build_clip_library.py` turns every `BlupiController::AnimState` (read from
`BlupiController.cpp`) into a clip by playing that icon table at 20 fps; `export_cna_avatar.py`
writes `avatars3d/blupi/` and the vehicles under `avatars3d/blupi/vehicles/`. The exact command
lines are in `avatars3d/blupi/README.md`. Rebuilding Blupi is expensive and risky: compare the new
output clip by clip with the committed one before replacing anything (the committed library was
assembled from builds of different days).

**Objects.** `tools/rd4_to_gltf/objects.txt` is the input table: one line per object (name,
sprite sheet, icon range, scene files, options such as `yaw=`, `tone=`, `camera=`, `min_iou=`).
`build_object_library.py` matches every icon to scene frames and cameras and writes a model per
object; `export_objects.py` exports them to `avatars3d/objects/<name>_<scene>/` with an `icons.txt`
(which pose draws which sprite icon, mirror, yaw, match quality) and rewrites `index.txt`. Commands
are in `avatars3d/objects/README.md`. A new object: add a line to `objects.txt`, build without
`tone=`, run `calibrate_tone.py` (vehicles: `calibrate_vehicle_tone.py`), add the suggested `tone=`,
rebuild, compare. `lower_spheres.py` tessellates spheres to their size for speed.

Special cases: `sign_decals.py` (the mission and world signs' painted digits and pictures as
decals), `dynamite_sparks.py` and `electro_sparks.py` (painted sparks cut from the sprites as
camera-facing decals), `top_texture.py` (an original texture over a model seen from above, used for
the clay bridge), `survey.py` (what the converter can read and which scene each sprite came from),
`posed_bounds.py` (a model's size as drawn), `d11_candidates.py` (models that differ most from their
sprites).

Parity reports (generated): `python3 tools/model_parity.py > plans/inventory/model_parity.md`
(every model with its source scene and silhouette IoU) and
`python3 tools/asset_inventory.py` (writes `plans/inventory/assets.md`; `--check` fails when it is
stale; it does no other option parsing, so even `--help` rewrites the file). On 2026-11-07 `--check`
reports the committed `assets.md` stale (it lacks the later bridge, door, drip and conveyor models). `tools/audit/model_sources.py` lists every original scene and whether the game draws it.

## Terrain reliefs: `tools/terrain_relief/`

Each terrain tile that has an original scene is drawn near the camera as that scene's relief.
`tiles.txt` says which scene belongs to which tile icon (reviewed by eye), `match_tiles.py` ranks
candidate scenes by pixel structure, `build_relief.py` builds each relief from the object library
(front half only, decimated to about 700 triangles, cut along the cell edges, textured by the tile's
sprite) and writes `avatars3d/terrain/*.gtr` and its `index.txt`; `blender_decimate.py` is the
headless Blender step (`blender -b --python ...`). `reliefs.txt` holds per-model options of `build_relief.py` (for example which scene props to drop). The
commands are in `avatars3d/terrain/README.md`. Tiles without a scene stay textured cubes.

## Other generators

- `tools/music/render_music.py <midi...> --out <dir> [--soundfont ...] [--ogg]` renders the original's
  MIDI tracks with libfluidsynth (through `ctypes`, so only the library is needed) and a General MIDI
  soundfont into WAV, optionally OGG (needs `ffmpeg`). Output names are `musicNNN.*`. A world's
  music track is stored in its header ([05-worlds.md](05-worlds.md)); the web build does not pack the
  music, it fetches a track when first played.
- `tools/bolt/bolt_paths.py` thins the lightning sprites (icons 305-307 of `object-m.png`) to
  centre lines and writes `BoltPaths.hpp`; `tools/glue/glue_strands.py` does the same for the glue
  death's strands (`GlueStrands.hpp`).
- `tools/a3d/a3d.py` reads the original Amapi 3D shapes (format notes in
  `plans/audit/a3d_format.md`); `tools/a3d/lava_surface.py` writes `LavaSurfaceData.hpp`, the lava's
  wave frame by frame.
- `tools/DumpBlockDefinitions.cpp` (a C++ executable) exports the block registry to
  `tools/data/blocks.csv`.

## Inventories and audits of assets

`plans/inventory/assets.md` (every converted model with source, clips, IoU), `plans/inventory/worlds.md`
(`tools/world_inventory.py`), `plans/inventory/model_parity.md`, and the ledgers
`plans/audit/asset_sources.csv` (every original 3D source and what became of it, generated by
`tools/audit/asset_sources.py`), `plans/audit/model_sources.md`, `plans/audit/render_representation.csv`
(how each of the 441 block icons and the object models is drawn), `plans/audit/blupi_animations.md`.
The 56 `.max` (3D Studio MAX) sources cannot be read and are not converted; the owner closed that
item (`plans/audit/manual_review.md`, MR-0001/MR-0010): the charge and shield effects stay the
original's sprites.

## Where the originals are (not read for this handbook)

The commands above name `../speedyblupi-data/originals` (scenes) and
`../mobile-eggbert/Content/icons` (sheets). Those repositories are read-only inputs. Several tools
also take `--cna-home` (the CNA checkout) for its avatar converter. Without those siblings you can
still build and play the game and run every test except the two that read `../mobile-eggbert`;
you cannot regenerate models.

## Effects that stay sprites

Explosions, splashes, sparks, the charge and the shield are billboards by decision (2026-10-24;
the 3D sources for the last two were not available). Procedural textures (bark, wood grain, metal
noise) stay flat colours: an approximate bake measured worse than the sprite.
